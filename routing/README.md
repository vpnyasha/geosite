# Routing profile

`kimiko.json` — профиль маршрутизации, который клиенты применяют у себя. Формат общий для
Happ и INCY: `Name`, `GlobalProxy`, `DirectSites`/`ProxySites`/`BlockSites`, `Geositeurl`,
`Geoipurl`, DNS-пары Remote/Domestic, `DomainStrategy`, `LastUpdated`.

Раздаётся двумя путями, и они дополняют друг друга:

- **Happ** получает его заголовком `Routing` из настроек подписки (`happRouting` в панели) —
  статический снимок, обновляется только когда мы правим панель.
- **INCY** получает заголовком `autorouting` со ссылкой на этот файл. Приложение проверяет
  источник каждые 30 минут и обновляет профиль (по умолчанию раз в сутки), решая по
  `LastUpdated`, есть ли что применять.

## Правка

**`LastUpdated` обязан вырасти при каждом изменении** — INCY применяет профиль, только если
значение больше сохранённого. Забыть его = молча раздать старые правила.

Профиль в панели (`happRouting`) и этот файл должны совпадать, иначе Happ и INCY разъедутся.
Панель — источник правды: файл выгружается из неё, а не наоборот.

Ссылка в заголовке ведёт на jsDelivr с веткой `main`, чтобы правка файла доезжала до людей
без смены ссылки в панели. Для `geosite.dat` так делать нельзя — он пиненный по тегу, потому
что подменённый список правил дороже, чем неудобство ручного обновления.
